# Ревью ответа AI

## Общая оценка

Ответ AI можно использовать как хорошую основу для дальнейшей подготовки тестовой документации.

Модель охватила основные позитивные и негативные сценарии, добавила проверки API, UX и часть граничных значений. Однако полученный результат нельзя считать полноценным тестовым покрытием без дополнительного анализа и доработки.

## Что AI сделал хорошо

1. Разделил проверки по категориям:
   - позитивные сценарии;
   - негативные сценарии;
   - граничные значения;
   - UX;
   - API.

2. Учёл основные ограничения по весу груза и объёму груза.

3. Добавил проверки автокомплита для выбора городов.

4. Учёл обработку ошибки «Маршрут не найден».

5. Добавил проверки сетевых ошибок и таймаутов API.

6. Добавил UX-проверки:
   - отображение ошибок;
   - наличие лоадера;
   - адаптивность интерфейса;
   - клавиатурную навигацию.

## Что AI упустил

1. Не проверил сценарий, когда город отправления совпадает с городом назначения.

2. Не указал ожидаемое поведение при отсутствии результатов в автокомплите.

3. Не проверил работу поиска городов при разном регистре символов.

4. Не проверил ограничения на количество знаков после запятой для веса и объёма.

5. Не проверил ввод чрезмерно больших числовых значений.

6. Не проверил возможность вставки значений через буфер обмена.

7. Не указал поведение кнопки «Рассчитать стоимость» при незаполненных обязательных полях.

8. Не проверил формат отображения итоговой стоимости.

9. Не описал обработку различных кодов ответа API (400, 404, 500).

10. Не проверил защиту от повторной отправки запросов при многократном нажатии кнопки расчёта.

## Что я бы уточнил

1. Проверка выбора текущей даты зависит от бизнес-требований и требует дополнительного уточнения.

2. Проверки XSS и SQL-инъекций для поля выбора города выглядят избыточными для MVP формы и требуют подтверждения рисков со стороны разработки.

3. Проверки адаптивности и клавиатурной навигации являются полезными, но имеют меньший приоритет по сравнению с проверками основной бизнес-логики расчёта перевозки.

## Дополнительные проверки

Я бы дополнительно включил:

1. Совпадение города отправления и города назначения.
2. Отсутствие результатов в автокомплите.
3. Выбор города исключительно из справочника.
4. Проверку минимально допустимых значений веса и объёма.
5. Проверку дробных значений веса и объёма.
6. Проверку доступности кнопки расчёта до заполнения обязательных полей.
7. Проверку повторного расчёта после изменения параметров заявки.
8. Проверку корректного отображения стоимости в рублях.
9. Проверку различных ошибок API.
10. Проверку блокировки повторных запросов во время выполнения расчёта.

## Вывод

AI подготовил качественную стартовую заготовку и охватил большинство базовых сценариев. Основные недостатки связаны с отсутствием части бизнес-проверок, недостаточной детализацией поведения автокомплита и неполным покрытием интеграционных сценариев.

Перед использованием такого чек-листа в проекте требуется дополнительное ревью и доработка со стороны QA-инженера.
