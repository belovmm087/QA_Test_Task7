# Анализ ошибок в методе РассчитатьСтоимость

## Ошибка 1. Использование текущей даты вместо даты заказа

В исходном коде используется:

```1c
Запрос.УстановитьПараметр("ДатаЗаказа", ТекущаяДата());
```

Проблема:

Стоимость доставки должна рассчитываться на дату заказа, а не на текущую дату выполнения метода.

Если заказ создан задним числом или запланирован на будущую дату, расчёт может вернуть неправильный тариф.

Исправление:

```1c
Запрос.УстановитьПараметр("ДатаЗаказа", ДатаЗаказа);
```

---

## Ошибка 2. Некорректная обработка границ веса через МЕЖДУ

В исходном коде используется:

```1c
&СуммаВес МЕЖДУ ЦеныДоставки.ВесОт И ЦеныДоставки.ВесДо
```

Проблема:

`МЕЖДУ` включает обе границы интервала.

Если есть интервалы `0-10` и `10-20`, вес `10` может попасть сразу в оба интервала.

По условию задачи вес `10` должен попадать в интервал до `10`, а не от `10`.

Исправление:

```1c
&ОбщийВес > ЦеныДоставки.ВесОт
И &ОбщийВес <= ЦеныДоставки.ВесДо
```
Нижняя граница интервала не включается, верхняя включается. Поэтому значение 10 попадёт в интервал до 10, а значение 10.1 попадёт в следующий интервал.

---

## Ошибка 3. Отсутствует ограничение результата одной записью

В исходном запросе есть сортировка:

```1c
УПОРЯДОЧИТЬ ПО
    Период УБЫВ
```

Проблема:

Сортировка сама по себе не ограничивает результат.

Запрос может вернуть несколько подходящих записей, а код возьмёт первую строку выборки.

Лучше явно указать, что нужна только одна актуальная запись.

Исправление:

```1c
ВЫБРАТЬ ПЕРВЫЕ 1
    ЦеныДоставки.Стоимость КАК Стоимость
```

---

## Ошибка 4. Некорректная обработка веса больше максимального интервала

По условию задачи, если вес выходит за максимальный известный интервал, стоимость не определена.

В исходном коде при отсутствии результата возвращается:

```1c
Возврат 0;
```

Проблема:

`0` может быть воспринят как реальная стоимость доставки.

Это смешивает два разных состояния:

- доставка бесплатная;
- стоимость не определена.

Исправление:

```1c
Возврат NULL;
```

или явно обрабатывать ошибку расчёта стоимости.

---

## Ошибка 5. Непонятная установка параметра ТипКлиента

В исходном коде используется:

```1c
Запрос.УстановитьПараметр("ТипКлиента",
СправочникКлиенты.НайтиПоРеквизиту(...));
```

Проблема:

Параметр `ТипКлиента` должен соответствовать типу значения, который хранится в регистре сведений.

Если в регистре хранится перечисление или строковое значение, а в параметр передаётся ссылка на клиента, отбор может работать некорректно.

Исправление:

Передавать именно тип клиента:

```1c
Запрос.УстановитьПараметр("ТипКлиента", ТипКлиента);
```

---

## Ошибка 6. Нет проверки пустой табличной части

В исходном коде сумма веса рассчитывается по табличной части:

```1c
СуммаВес = 0;
Для каждого Строка из ТабличнаяЧасть.Номенклатура Цикл
    СуммаВес = СуммаВес + Строка.Вес;
КонецЦикла;
```

Проблема:

Если табличная часть пустая, вес останется равным `0`.

Далее запрос будет искать тариф для веса `0`, хотя заказ без номенклатуры не должен рассчитываться как корректный.

Исправление:

Перед расчётом нужно проверить наличие строк и положительный вес.

---

## Ошибка 7. Нет проверки отрицательного или пустого веса

Проблема:

Если в строке табличной части вес не заполнен или указан отрицательным значением, метод всё равно прибавит его к общей сумме.

Это может привести к некорректному расчёту доставки.

Исправление:

Проверять, что вес каждой строки заполнен и больше нуля.

---

## Ошибка 8. Нет явной обработки ситуации с несколькими тарифами на одну дату

Проблема:

Если в регистре есть несколько записей с одинаковым периодом, типом клиента и весовым интервалом, запрос может вернуть неоднозначный результат.

Исправление:

На уровне данных нужно запрещать дублирующиеся интервалы или добавлять дополнительное правило выбора записи.

---

## Итог

В исходной реализации есть несколько потенциальных проблем:

- неправильная дата расчёта;
- некорректная работа с границами веса;
- отсутствие ограничения результата;
- неоднозначный возврат `0`;
- возможное несоответствие типа параметра `ТипКлиента`;
- отсутствие проверок табличной части;
- отсутствие контроля отрицательного веса;
- возможные дубли тарифов.

Критичными являются ошибки с датой заказа, границами веса и возвратом `0` вместо признака неопределённой стоимости.
