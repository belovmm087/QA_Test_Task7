# Ревью чек-листа API

## Общая оценка

Чек-лист составлен на основе REST-подхода и покрывает основные сценарии жизненного цикла заказа через контроллер `/api/v2/orders`.

Проверки охватывают успешные сценарии работы, ошибки валидации, проблемы авторизации, отсутствие прав доступа, работу с несуществующими ресурсами и технические сбои.

## Почему выбраны именно эти статус-коды

### 200 OK

Используется при успешном получении или изменении данных.

Примеры:

- GET /api/v2/orders
- GET /api/v2/orders/{id}
- PUT /api/v2/orders/{id}

### 201 Created

Используется при успешном создании нового заказа через POST-запрос.

Пример:

- POST /api/v2/orders

### 204 No Content

Используется при успешном выполнении операции без тела ответа.

Примеры:

- DELETE /api/v2/orders/{id}
- HEAD /api/v2/orders/{id}

### 400 Bad Request

Используется при ошибках валидации входных данных:

- отсутствуют обязательные поля;
- передан некорректный UUID;
- нарушены ограничения модели данных.

### 401 Unauthorized

Используется при отсутствии или некорректности авторизационных данных.

### 403 Forbidden

Используется когда пользователь авторизован, но не имеет необходимых прав для выполнения операции.

### 404 Not Found

Используется при обращении к несуществующему заказу.

### 410 Gone

Используется для логически удалённых заказов, если такая бизнес-логика предусмотрена системой.

### 500 Internal Server Error

Используется при внутренних ошибках сервиса:

- недоступность БД;
- необработанные исключения;
- ошибки интеграций.

## Дополнительные проверки

Помимо базовых сценариев рекомендуется проверить:

- корректность Content-Type;
- единый формат ошибок API;
- обработку неподдерживаемых HTTP-методов;
- время ответа сервиса;
- идемпотентность PUT и DELETE операций;
- корректность логирования ошибок;
- наличие обязательных полей в ответе согласно контракту API;
- отсутствие неожиданных полей в ответе;
- корректность форматов UUID;
- корректность форматов даты и времени;
- соответствие структуры ответа опубликованной спецификации API.

## Вывод

Чек-лист покрывает основные требования REST API и соответствует распространённым практикам проектирования API, описанным в Google REST API Design Guide и Microsoft REST API Guidelines.

Дополнительно были включены проверки контрактов API, структуры ответов, кодов ошибок и идемпотентности операций. Это позволяет выявлять не только функциональные дефекты, но и нарушения API-спецификации и обратной совместимости сервиса.
